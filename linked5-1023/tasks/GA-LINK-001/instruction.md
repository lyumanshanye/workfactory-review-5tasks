# Dota 2平衡复核：将历史对局信号转成六项受控试玩假设

你是游戏平衡团队的数据分析师。设计负责人只给六个受控试玩假设名额，希望先验证历史对局中的信号，再决定是否研究数值调整。材料来自UCI 2016数据快照，不是当前版本数据；交付是试玩优先事项，不是上线削弱/增强名单。此业务安排为本练习假设。

工作要求：
1. 追溯UCI网页实际引用的采集代码/英雄映射URL，核实资料角色和格式。逐个检查原始train/test CSV的行数、列数、标签、类别、英雄符号、每方人数、缺失、精确重复及跨split精确行交集。相同编码不等于同一真实对局，缺少match ID时不得声称已排除所有对局泄漏。两份CSV无表头；先按UCI说明理解117列，注意被引用采集代码未必直接输出该格式。
2. 英雄列统一编号H001至H113，对应CSV第5至117列（1起算）；可以在有证据时加名称，但不能将映射JSON列表位置或未核实ID关系硬套为英雄名。列1结果+1/-1与英雄符号+1/-1对应的胜方要明确。
3. 用训练集确定基线并挑选六个假设。分层键为cluster、game_mode、game_type（三个原始编码列）；层内训练样本>=100时，以该层+1方胜率作基线，否则用训练集总体+1方胜率。对某英雄的每次出场，若在+1方则预期胜率p，若在-1方则1-p；英雄原始胜率减逐次预期平均值，得到校正差（百分点），这只是分层关联差，不是因果效果。
4. 训练合格标准：出场>=1000且在每一方出场>=200。按校正差选最高三项、最低三项（不得重复），并列按H编号升序。清单只能由训练数据决定。对全部113项报告训练支持度、两方支持度、原始胜率、预期率、校正差；对选中六项再报告训练/测试两边的同类统计、原始胜率95% Wilson区间（z=1.96）、分方校正差及稀疏层回退占比。
5. 测试集只作一次保留集复核，沿用训练基线，不重选六项或重估基线。稳定性标记仅在测试出场>=100且校正差与训练严格同号时为“方向复现”；否则为“未复现/支持不足”。Wilson区间针对原始胜率，不是校正差的显著性区间；六项是探索性多重比较，不能据此宣布因果或统计显著。
6. 将六项各转成一个受控试玩假设，列训练证据、测试复核、应检查的阵营/分层混杂、对照设计、主要观察指标、支持/推翻假设的条件、拟负责角色和优先级。优先级可自行解释，不影响既定六项；说明2016时窗、版本/玩家/角色信息缺失、英雄映射和对局去重的限制，不能将信号直接泛化当前版本。

## 可用材料

输入仅位于只读的 `/app/input_files/`，下列全部文件均已提供。不得修改原件；联网不是完成任务的前提，不需要重新下载或更新数据。

| 文件 | 说明 |
|---|---|
| `dota2Train.csv` | UCI原始训练split，无表头；列1胜方，列2cluster，列3mode，列4type，列5起113个英雄指示列。 |
| `dota2Test.csv` | UCI原始保留split，同结构；只用于冻结清单后的复核。 |
| `uci_dota2_dataset.html` | UCI说明网页快照，正文实际引用采集代码与映射文件，并给原始下载。 |
| `dota2_collector_page.html` | UCI所引GitHub gist原始网页快照；核实其格式而非默认等同CSV生成器。 |
| `heroes_mapping.json` | UCI所引仓库英雄映射文件快照；ID与指示列的关系须独立核实。 |
